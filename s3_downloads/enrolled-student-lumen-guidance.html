3. Standard Onboarding Sequence

  1. Learner completes the applicable admission/enrolment formalities.
  2. BITS Student ID and official BITS email credentials are generated as part of onboarding.
  3. The onboarding communication is sent to the learner’s registered personal email address.
  4. Learner activates the BITS mailbox and begins using the BITS email ID for official programme communication.
  5. Learner accesses Lumen using the BITS email authentication option (commonly shown as “Login using BITS Mail”).
  6. Course information, learning resources, orientation/session recordings and programme communications become available through the relevant systems.

Counsellor wording: “Please check your registered personal email address, including Spam/Junk, for the onboarding communication from BITS Pilani Digital.”

4. Lumen Access: What Counsellors Should Tell Learners

  • Lumen is the LMS used for course content, academic resources, recordings and other learning-related information.
  • Once the BITS email ID is activated, learners should access Lumen using their BITS email credentials / “Login using BITS Mail” option.
  • If a learner has no BITS email credentials yet, first resolve onboarding; Lumen access may remain unavailable until the BITS email is active.
  • If the BITS email is working but Lumen does not open, shows no courses, shows an old preparedness/bridge course only, or displays the wrong course, treat it as an LMS/course-mapping issue and route to the relevant programme team.
  • Ask the learner to share a screenshot of the Lumen dashboard/error whenever possible.
  • Do not invent a live-session link, meeting link, course code or LMS workaround.

7. Common Scenarios & Correct Counsellor Response

A. Learner has received nothing — Ask for Application Number, programme name and registered mobile number. Ask them to check registered email + Spam/Junk. State that onboarding/BITS email/Lumen status will be checked. If classes are imminent, mark urgent.

B. Student ID exists, but official BITS email has not arrived — Acknowledge that Student ID is generated but email credentials are pending. Escalate BITS email activation and Lumen status. Do not tell the learner to create a new identity themselves.

C. BITS email is active, but Lumen does not work — Route to programme team from BITS email. Ask for Student ID and screenshot/error. Do not keep the learner in Admissions for an academic-system mapping issue.

D. Lumen opens, but no active courses appear — Treat as mapping/course enrolment issue. Programme team should review. New First Trimester learners are automatically registered; do not ask them to manually register First Trimester courses.

E. Old Preparedness / Bridge course is visible, but current M.Sc. courses are missing — Route to msc_dsai@bitspilani-digital.edu.in with screenshot and Student ID. Do not assume the old access is the correct current LMS mapping.

F. Learner asks for orientation recording — Guide them to Lumen. If recording is not visible after access is active, route to the relevant programme team.

G. Learner gets a live-session registration error — Ask for screenshot and route to relevant programme team from BITS email. Do not generate or guess a meeting link.

H. Learner asks where study notes are or disputes an answer/assessment — This is academic. Route to programme team from BITS email with course/topic/question and screenshot.

I. Learner says 'I need human guidance' — Acknowledge the request and escalate to the appropriate human/onboarding/programme team depending on whether the issue is credentials or academics.
